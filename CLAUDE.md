# Bytecraft — правила для Claude Code

Мобильная игра для обучения Python короткими головоломками. Flutter (iOS + Android), Riverpod, чистый Dart в domain.
Подробно: `README.md`, `docs/ARCHITECTURE.md` (ADR-1…13), `docs/DESIGN.md`, `docs/TOPIC_STYLE.md`, `docs/RELEASE.md`.

## Команды

| Что | Команда |
|---|---|
| Анализ и тесты | `flutter analyze && flutter test` |
| Перегенерировать курс (исполняет каждый сниппет) | `python3.12 tool/content/generate_python_course.py assets/content/python` |
| Проверить, что ассеты совпадают с генератором | сгенерировать во временную папку и `diff -r <tmp> assets/content/python` |
| Смоук на устройстве | `flutter test integration_test/device_smoke_test.dart` |

Генератор требует ровно Python 3.12. CI (`.github/workflows/android.yml`) повторяет проверку курса, гоняет программы в Pyodide и собирает APK.

## Жёсткие правила

- `assets/content/python/` — генерируемый файл. Правится только `tool/content/`, потом перегенерация. Хук не даст отредактировать ассеты руками.
- Все числа экономики (XP, монеты, жизни, цены, бонусы) — только в `GameRules` (`lib/features/gamification/domain/game_rules.dart`). Перед изменением баланса — `/balance-check`.
- Domain — чистый Dart без Flutter, с юнит-тестами. Время — через `Clock`, не `DateTime.now()`.
- UI берёт цвета, отступы и шрифты из `lib/core/theme/`. Литералы `Color(0x…)` вне темы не добавлять.
- Не пушить в `main`, не делать force push, не коммитить без просьбы пользователя.
- Ключи подписи (`*.jks`, `key.properties`) не читать и не коммитить.

## Как работаем

Вопрос → варианты → решение пользователя → черновик → одобрение. Перед изменением нескольких файлов покажите список изменений.

Визуальная задача не считается готовой, пока экран не запущен и не проверен на скриншоте (узкий экран 320 dp и масштаб шрифта 200 %). Если запустить нельзя — так и скажите: **NOT ASSESSED**, а не «всё хорошо». Отсутствие проверки не равно успешной проверке.

## Команда агентов и скиллы

- Агенты (`.claude/agents/`): `economy-designer` (баланс), `ux-reviewer` (экраны и доступность), `qa-lead` (тест-план и Definition of Done). Ревьюеры только читают код и не правят его.
- Скиллы: `/balance-check`, `/ux-check`, `/bug-report`, `/release-checklist`.
- Правила по путям лежат в `.claude/rules/` и подгружаются сами при работе с соответствующими файлами.

## Чекпоинт длинной задачи

Для задачи дольше одной сессии ведите `.claude/state/active.md` (не коммитится): цель, что сделано, что дальше, открытые вопросы. Хук `SessionStart` показывает его после старта, `/clear` и сжатия контекста. Файл — память, а не разговор.
